# 면접관 영상

> **이 폴더의 파일은 직접 넣거나 고치지 마세요.**
> 원본은 `_source/video/` 에 있고, `tools/build_assets.py` 가 여기로 만들어 냅니다.
> 새 영상 편입 절차는 `tools/README.md`.

## 구조

```
video/<form>/<persona>/<key>.mp4

  form    : human | avatar
  persona : middle_man | young_woman | young_man
  key     : intro · 1-1 · 1-2 · 2-1 · 2-2 · 3-1 · 3-2   (질문 낭독, 음성 포함)
            wait                                       (다시듣기 대기 = 질문 직후 5초, 눈 깜빡임만, 무음 loop)
            idle                                       (답변 대기 = 참가자 답변을 듣는 장면, 무음 loop)
```

정지 사진 `assets/persona/<form>_<persona>.jpg` 는 `idle.mp4` 첫 프레임입니다.
블러(저장·평가) 화면과 사진 모드에서 쓰이며, 대기 영상과 구도가 정확히 같습니다.

## 면접관 배정 (전 조건 동일)

| 면접관 | 인물 | persona | 좌석 | Multi 담당 문항 |
|---|---|---|---|---|
| 면접관 1 | 중년 남자 | `middle_man` | 왼쪽 | 자기소개(intro), 1-1, 1-2 |
| 면접관 2 | 젊은 여자 | `young_woman` | 가운데 | 2-1, 2-2 |
| 면접관 3 | 젊은 남자 | `young_man` | 오른쪽 | 3-1, 3-2 |

Single 조건은 배정된 페르소나 1명이 7문항 전부를 담당하므로, **페르소나마다 7문항이 모두** 필요합니다.

## 대기 영상 (wait.mp4 · idle.mp4)

대기 클립은 **기본 자세로 시작·끝**나고, 질문 영상은 **기본 자세로 끝나지만 시작은 이미 말하는 자세**입니다
(2026-09-28 측정: 기본 자세와의 차이 시작 6~8 / 끝 ~5). 그래서 질문 → 대기는 바로 이어지고,
대기 → 질문은 블러 뒤에서 바꿔 치웁니다 (아래 재생 규칙).

| 파일 | 언제 | 내용 |
|---|---|---|
| `wait.mp4` | 질문 직후 **다시 듣기 선택 5초** | 눈 깜빡임만 있는 5초 클립. 자세가 거의 변하지 않아 언제 [다시 듣기]를 눌러도 질문 영상으로 튀지 않음 |
| `idle.mp4` | **답변 중** | 5초 클립(필기·끄덕임 등)을 번호순으로 이어 붙인 loop (24fps × 121프레임 × 클립 수) |

- 대기 클립은 질문 영상보다 약 10단계(0~255) 밝게 나와 있어, `build_assets.py` 가 질문 영상 색에 맞춰 보정합니다.
- 소리 트랙은 제거하고 브라우저에서 `muted loop` 로 재생합니다.

### 재생 규칙 (index.html)

| 시점 | 동작 |
|---|---|
| 로그인 직후 ~ 면접 시작 전 | 그 조건의 질문·대기 영상을 **전부 미리 받아 메모리에 둠** (안내 음성 106초 동안). 다 받기 전엔 면접 화면으로 안 넘어감 (최대 90초) |
| 카운트다운 · 저장 블러 중 | 다음 질문 영상을 미리 받아 **첫 프레임을 블러 뒤에 띄워 둠** (질문 영상은 첫 프레임부터 말하는 자세라 기본 자세와 다름 → 자세 변화를 블러로 가림) |
| 답변 중 | 다음 질문 영상을 미리 받아 둠 (재생 지연 방지) |
| 질문 영상 재생 중 | 뒤의 wait·idle 을 멈추고 첫 프레임으로 되감아 둠 |
| Multi 나머지 면접관 | **질문 중 · 다시 듣기 선택 중에는 정지 사진**(기본 자세), 답변이 시작되면 전원 idle 재생. 눈 깜빡임 클립(5·10·15초)이 오면 정지 사진 자리를 대체 예정 |
| 질문 영상 끝 | 즉시 `wait` 로 전환 (다시 듣기 5초 동안 loop) |
| [다시 듣기] 클릭 | `wait` → 질문 영상 ⚠ 질문 영상 첫 프레임이 기본 자세가 아니라 여기서는 약간 튐 (영상 재제작으로만 해결) |
| 답변 시작 | **4초 동안 정지 화면 유지**(`ANSWER_STILL_SEC`) 후 전원 `idle` 시작 — 시작 클립만 무작위(클립 경계), 순서는 고정 loop. 클립은 시작 후 0.6~3.5초에 움직이므로 첫 동작은 답변 시작 약 4.6초 이후. 로그 `idle_start` |
| 저장·평가 블러 | 전부 정지, 정지 사진(= idle 첫 프레임) 표시. 블러가 걷히면 비발화 면접관도 시작 클립을 새로 뽑음 |

## 질문 영상

- 영상 속 음성은 `assets/audio/voice/<persona>/<key>.mp3` 와 **같은 녹음**이어야 합니다.
  (오브 조건과 사진 모드는 mp3 를, 영상 모드는 영상 내장 음성을 씁니다.)
- 제작 사이트의 파일 번호는 문항 순서와 다를 수 있습니다. `ingest_assets.py` 가 파형 대조로 문항을 정합니다.
- 워터마크가 없어야 합니다 (조건 간 자극 차이).

## 규격

| 구분 | 현재 |
|---|---|
| 질문 영상 | H.264 + AAC, 1920×1080, 25fps |
| 대기 영상 (wait·idle) | H.264, 1916×1080, 24fps, 무음, 색 보정 후 재인코딩(CRF 18) |
| 공통 | faststart (다 받기 전에 재생 시작) |

`build_assets.py --height 720` 으로 만들면 전부 1280×720 으로 재인코딩됩니다 (용량 약 1/6).

## 브라우저 캐시

`vercel.json` 이 `assets/` 를 1년 immutable 로 캐시합니다. 같은 경로의 파일을 교체하면 이미 받은 브라우저는
옛 파일을 계속 씁니다. 그래서 모든 자산 주소 뒤에 `?v=ASSET_VERSION` 을 붙이고,
`build_assets.py` 가 파일을 새로 만들 때마다 index.html 의 `ASSET_VERSION` 을 자동으로 바꿉니다.
**자산을 손으로 교체했다면 `ASSET_VERSION` 도 손으로 바꿔야 합니다.**

## 파일이 없을 때의 동작

한 조건에 필요한 영상이 하나라도 없으면 **그 조건 전체가 정지 사진 + mp3 모드로 내려갑니다.**
한 조건 안에서 일부만 영상이면 참가자마다 자극이 달라지기 때문입니다.
영상을 다 채우면 코드 수정 없이 영상 모드로 돌아가며, 진행 로그에 `video_mode` / `photo_mode` 가 남습니다.
