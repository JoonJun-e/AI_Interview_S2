# 조건 자동 배정 + 녹음 수집 설치 가이드

구글 계정 하나로 동작합니다. **카드 등록·서버·새 저장소가 필요 없습니다.**

- 참가자에게 **링크 하나만** 배포
- 접속하면 참가자 번호가 자동 생성되고, **인원이 가장 적은 조건**에 배정
  (조건 C1~C6, Single 은 페르소나 3명으로 다시 나뉘어 **배정 버킷 12개**)
- 조건은 URL에 드러나지 않고 앱 내부에만 전달
- 답변 녹음은 문항이 끝날 때마다 **구글 드라이브에 자동 업로드**
- 배정·업로드·진행 로그가 **구글 스프레드시트**에 쌓임

> **현재 상태 (2026-09-28): 연결 확인됨.** Apps Script 프로젝트 `Condition assign` 의 웹앱 배포(버전 3)를
> `deploy/index.html` 의 `BACKEND_URL` 이 가리키고 있습니다. 실행 계정은 소유자, 액세스 권한은 **모든 사용자**.
> `GET /exec` 이 `{"ok":true,"message":"AI Interview S2 backend"}` 를 반환하는지로 살아 있는지 확인할 수 있습니다.
>
> ⚠️ **재배포하면 `/exec` 주소가 바뀝니다.** `Code.gs` 를 고쳐 **배포 관리 → 새 버전**으로 배포한 뒤에는
> 반드시 새 주소를 `BACKEND_URL` 에 반영하세요. 반영을 빠뜨리면 프런트가 옛 주소를 호출하고,
> 구글이 JSON 대신 오류 HTML(404/405)을 돌려주기 때문에 참가자 화면에 `ASSIGN_FAILED` 가 뜹니다.
> 2026-09 에 실제로 이 일이 있었습니다.

소요 시간 약 5분. **1·2단계는 이미 만들어 두었습니다.**

## 2. 구글 스프레드시트 — 생성 완료 ✅

[AI면접_배정기록](https://docs.google.com/spreadsheets/d/1mD3lP4jtQiDVYcUeQ6VJ_Br1i0qh9nthAOHOZ4UoZu0/edit)
`1mD3lP4jtQiDVYcUeQ6VJ_Br1i0qh9nthAOHOZ4UoZu0`

탭(assignments·uploads·logs)은 첫 실행 때 자동으로 생성됩니다.

`assignments` 탭의 칸 구성:

| 시각 | 참가자 | 이름 | 조건 | 면접관수 | 형태 | 페르소나 | 브라우저 | 배정순번 | 뒷4자리 |
|---|---|---|---|---|---|---|---|---|---|

- **이름 · 뒷4자리** 는 참가자가 로그인할 때 채워집니다. 둘 다 필수 입력입니다.
- 이미 같은 이름이 있으면 뒤에 알파벳이 붙습니다 — `홍길동` → `홍길동B` → `홍길동C`.
  먼저 들어온 사람의 이름은 바꾸지 않으므로, 이미 내려받은 자료와 어긋나지 않습니다.
  재접속해도 한 번 정해진 이름은 그대로 유지됩니다.
- 누가 누구인지는 **뒷4자리**로 확인하세요. 알파벳은 시트에서 눈으로 구분하기 위한 것입니다.

## 3. Apps Script 붙여넣기

1. 위 **AI면접_배정기록** 스프레드시트를 엽니다
2. 상단 메뉴 **확장 프로그램 → Apps Script**
3. 기존 코드를 모두 지우고, 이 폴더의 `Code.gs` 내용을 전부 붙여넣습니다
   (ID 두 개는 이미 채워져 있으니 수정할 것이 없습니다)
4. 저장 (⌘S)

## 4. 웹앱으로 배포

1. 우측 상단 **배포 → 새 배포**
2. 톱니바퀴 아이콘 → **웹 앱** 선택
3. 설정
   - 설명: `AI Interview S2`
   - **다음 사용자로 실행: 나**
   - **액세스 권한: 모든 사용자** ← 반드시 이렇게
4. **배포** 클릭 → 권한 승인 (구글 계정 선택 → 고급 → 안전하지 않은 페이지로 이동 → 허용)
5. 발급된 **웹 앱 URL**을 복사합니다

```
https://script.google.com/macros/s/AKfycb..../exec
```

> "안전하지 않은 페이지" 경고는 본인이 만든 스크립트라 정상입니다.

## 5. 앱에 연결

`deploy/index.html` 을 열고 상단의 한 줄만 채웁니다.

```js
const BACKEND_URL = "https://script.google.com/macros/s/AKfycb..../exec";
```

저장 후 깃허브에 푸시하면 Vercel이 자동 배포합니다.

## 동작 확인

배포된 주소에 접속했을 때:

- 시작 화면에 **참가자 번호 P0001** 이 자동으로 표시됨
- 조건 선택 UI가 보이지 않음
- 스프레드시트 `assignments` 탭에 한 줄이 추가됨
- 면접을 끝까지 진행하면 드라이브 `P0001` 폴더에 녹음 7개가 들어옴

시크릿 창으로 다시 접속하면 P0002가 생성되고 **다른 조건**에 배정되는지 확인하세요.
같은 창에서 새로고침하면 **기존 조건이 유지**되어야 합니다.

## 배정 현황 보기

Apps Script 편집기에서 함수 `현황보기` 를 선택하고 실행하면
실행 로그에 조건별 인원이 표시됩니다. 스프레드시트를 직접 봐도 됩니다.

## 문제가 생기면

| 증상 | 원인·해결 |
|---|---|
| 참가자 번호 자리에 "배정 실패" | 웹앱 접근 권한이 **모든 사용자**인지 확인. 재배포 시 **새 버전**으로 배포해야 반영됨 |
| 드라이브에 파일이 안 생김 | `FOLDER_ID` 확인. 종료 화면 → 실험자용 에서 업로드 성공/실패 수를 볼 수 있음 |
| 조건이 한쪽으로 몰림 | 같은 브라우저로 반복 접속하면 기존 배정이 유지됩니다. 시크릿 창으로 테스트하세요 |
| 백엔드를 끄고 싶을 때 | `BACKEND_URL = ""` 로 비우면 예전처럼 실험자 수동 선택 모드로 돌아갑니다 |

## 안전장치

- **참가자는 어떤 경우에도 조건을 선택할 수 없습니다.** 운영 모드에서는 조건 선택
  UI 자체가 화면에서 제거됩니다.
- 배정에 실패하면 1.2초 간격으로 **3회까지 자동 재시도**하고, 그래도 실패하면
  "일시적인 오류" 안내 화면에서 진행이 막힙니다. 조건 선택 화면은 나타나지 않습니다.
- 업로드가 실패해도 면접은 중단되지 않습니다. 녹음은 브라우저에도 남아 있어
  종료 화면 하단 **실험자용** 메뉴에서 수동으로 내려받을 수 있습니다.

## 실험자 모드 (데모·테스트용)

주소 뒤에 `?admin=1` 을 붙이면 조건을 직접 골라 진행할 수 있습니다.

```
https://배포주소.vercel.app/?admin=1
```

**참가자에게 배포하는 링크에는 절대 붙이지 마세요.**
